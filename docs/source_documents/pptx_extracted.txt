Worked Example — Exam Hall Ticket Issue Register
Theme 1
THE PROBLEM
Hall tickets are held back at the counter on the morning of the exam, because a due or a shortage is found late. The student cannot fix it in time and loses the paper.
THE ONE RULE
A hall ticket is issued only if attendance is 75% or more in every registered subject, and there are no fee dues, no library dues and no disciplinary hold. One failing condition blocks it, and the reason must be shown.
The four engines
Engine 1 — Data & Integrity
DBMS
Tables for student, subject, attendance, dues and holds. Keys and constraints so a clearance cannot point at a missing student.
Engine 2 — Logic & Rule
Data Structures & Programming
Checks all four conditions and returns issue or block, plus every failing reason. Rule values read from a table, not typed in the code.
Engine 3 — Interface & Access
Web Technologies
Screens for student, clerk and controller. The server checks again, so a direct request cannot skip the rules.
Engine 4 — Testing & Validation
Software Engineering
Test table covering 74.9 / 75.0 / 75.1 attendance, the defect log, root cause notes and the report.

Worked Example — Library Catalogue Ranked Search
Theme 2
THE PROBLEM
Students search the catalogue by exact title. A small spelling mistake returns nothing, and when many copies match, the order is whatever the database returned — so a reference-only copy often appears above a lendable one.
THE ONE RULE
Results are ordered by a score the team designs — title match, availability, edition and copy count — and the same search must be shown in two different orders and compared.
The four engines
Engine 1 — Data & Integrity
DBMS
Tables for title, author, subject, edition, copy and availability, with keys so a copy cannot point at a missing title.
Engine 2 — Logic & Rule
Data Structures & Programming
Builds a word lookup over title and subject. Calculates the score, sorts the results and breaks ties.
Engine 3 — Interface & Access
Web Technologies
Search box and result list, with designed screens for "nothing found" and "too many found".
Engine 4 — Testing & Validation
Software Engineering
The fixed list of 20 test searches, the results table, the defect log and the report.

Worked Example — Lab Equipment Issue and Return Ledger
Theme 3
THE PROBLEM
Components are issued to students against a paper register. At the end of the year nobody can say who holds what, and the physical count never matches the register.
THE ONE RULE
Stock can never go below zero. Issue, return and receipt are all entries. The balance is receipts minus issues plus returns, calculated when it is shown — it is never stored as a number.
The four engines
Engine 1 — Data & Integrity
DBMS
Item, entry, user and audit tables. Foreign keys, a check that stops a negative issue, and entries that succeed or fail together.
Engine 2 — Logic & Rule
Data Structures & Programming
Calculates the balance from history. A queue gives oldest-first use and the list of what each student still holds.
Engine 3 — Interface & Access
Web Technologies
Issue, return and audit screens by role. The server checks again on every entry, so two requests cannot both take the last item.
Engine 4 — Testing & Validation
Software Engineering
Tests for negative stock, double issue and undo. Defect log, root cause notes and the report.

Worked Example — Attendance Shortage Report System
Theme 4
THE PROBLEM
Shortage lists come out late, are disputed by students, and are calculated differently by different staff. Three people produce three percentages from the same register.
THE ONE RULE
Attendance is classes attended over classes conducted — but cancelled classes, extra classes, students who joined late, and subject-wise versus overall attendance each give a different answer. The team must define the calculation, write down what it leaves out, and defend it.
The four engines
Engine 1 — Data & Integrity
DBMS
Reads the register, records what arrived — row count, columns, bad rows — and stores the cleaned data with keys and constraints.
Engine 2 — Logic & Rule
Data Structures & Programming
Calculates each report as a query, never a stored table. Recalculates every main number a second way and compares.
Engine 3 — Interface & Access
Web Technologies
Subject-wise and overall views by role, with every number on screen linked to the query behind it.
Engine 4 — Testing & Validation
Software Engineering
Tests with an empty file, a single row and a blank column. Defect log, root cause notes and the report.

Five Things to Remember
1
There are no marks for how it looks.
Not colours, not animations, not a login page that fades in.
2
Documents are dated.
A rule list written after the code is a description, not a plan.
3
You may use AI. You may not submit code you cannot explain.
That is the whole policy. Keep a short log of what you asked and what you changed.
4
Your engine is yours.
At every gate you answer for it alone. Those marks cannot be transferred.
5
Pick a rule, not a project.
Find something someone currently gets wrong, or does slowly by hand.
